= evil-weevil — Quick Start for Platform Maintainers
:toc:

== Overview

This guide covers packaging, deploying, and maintaining evil-weevil for
distribution on your platform.

== Runtime Dependencies

*None.* The shipped artefact is a C ABI shared library with no runtime dependencies
beyond the platform C library (ADR-0007). There is no interpreter, no VM, no garbage
collector and no daemon. The kernel allocates only from arenas the host supplies.

== Build from Source

[source,bash]
----
git clone https://github.com/metadatastician/evil-weevil.git
cd evil-weevil
just build-release
----

Output (once Phase 1 lands — not built yet):

[cols="1,1"]
|===
| Platform | Artefact

| Linux   | `lib/libevil_weevil.so`
| macOS   | `lib/libevil_weevil.dylib`
| Windows | `bin/evil_weevil.dll`
| WASM    | `evil_weevil.wasm` (injection mode C)
|===

== Packaging

=== Guix

[source,bash]
----
guix build -f build/guix.scm
----

=== Container (Stapeln)

[source,bash]
----
just stapeln-export    # Generates Containerfile
podman build -t evil-weevil .
----

=== Manual Package

[source,bash]
----
just install --prefix=/usr/local
----

Files installed:

[cols="1,2"]
|===
| Path | Contents

| `$PREFIX/lib/`
| `libevil_weevil.so` (+ `.a` if a static archive is offered)

| `$PREFIX/include/evil_weevil/`
| `ee.h` — the generated C ABI header hosts and adapters compile against

| `$PREFIX/share/doc/evil-weevil/`
| Documentation
|===

There is no `bin/` entry, no `.desktop` file and no man page: this is a library that a
host game loads, not an application.

== Configuration

There is no config file, no state directory and no environment variable. All
configuration is passed to `ee_init` by the host: declared ABI version, declared
capabilities (navmesh, line-of-sight queries, physics raycasts, waypoint graph, spawn
rights), budget, and the arena allocator. A library that writes to `$XDG_CONFIG_HOME`
inside somebody else's game is a surprise, not a feature.

== Health Checks

[source,bash]
----
just doctor            # Full diagnostic
just run --version   # Version check
just run --selftest  # Built-in self-test
----

== Updating

[source,bash]
----
git pull
just build-release
just install --prefix=/usr/local
----

Or via OPSM: `opsm update evil-weevil`

== Multi-Instance Deployment

Not applicable, and deliberately so. The library keeps no global state and writes
nothing outside the memory the host lends it, so instances are isolated by construction:
each host process links or loads its own copy, and two games on one machine cannot
interfere. If a deployment needs per-tenant tuning, that is configuration passed to
`ee_init`, not a second installation.
