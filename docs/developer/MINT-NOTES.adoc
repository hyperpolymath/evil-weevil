= Mint notes — evil-weevil from rsr-template-repo
:toc:

Measured on this repo's own mint, 2026-09-20.

*Parent:* `rsr-template-repo` · *parent-pin:* `06d8c9f7a8d2` (recorded in
`.machine_readable/descriptiles/VARIANT.a2ml`) · *outcome:* mint exit 0,
`just verify` PASS, all placeholders replaced.

This file exists because a mint is not finished when the script exits 0. It is finished
when the repo stops describing itself as something else.

== 1. Toolchain the mint needs

`just repo-init` is not a pure-shell operation:

[cols="1,3"]
|===
| Tool | Why

| `just` | the task runner; every phase is a recipe
| `rustc` | `scripts/rust-tool.sh` compiles two single-file Rust mint tools on demand
  (`strip-instruction-blocks`, `prune-dependabot-ecosystems`). A cached binary needs no
  toolchain; a cold cache does.
| `uuidgen` | derives the repo's UUIDv5 identity (`--sha1 --namespace @url --name`)
| `nickel` | *not* needed to mint, but needed by `just claude-md` to compile the arrival pack
|===

On a machine without them, the mint fails partway through — after substitution has
already begun — which is the worst place to stop.

== 2. The one trap, and it is documented

**Do not set `RSR_NON_INTERACTIVE=1`.** The template says so itself
(`README.adoc`, `docs/AI_INSTALLATION_GUIDE.adoc`) and the reason is in
`build/just/repo-init.just`:

[source,bash]
----
if [ -n "${RSR_NON_INTERACTIVE:-}" ]; then
    read() { return 0; }   # intended: silence the prompts
fi
----

That stub does not silence prompts; it replaces `read` for *every* `read` in the
script, including the file-walking loops (`find ... | while read -r file; do ... done`).
Two failures at once: the loop variable is never assigned (so `set -u` reports
`file: unbound variable`), and `read` returns success **without consuming stdin**, so
the loop never terminates. Measured: the substitution pass never runs and the process
spins until killed. Repro in twelve lines: the same loop behaves correctly the moment
the stub is removed.

*Consequence for us:* the mint is driven by piping 18 answers to stdin. The recipe's
stale "Non-interactive support" comment promises a mode that does not work, and the
honest fix upstream is to make the flag fail loudly or delete it — a flag that silently
converts a mint into an infinite loop is worse than no flag.

== 3. What survives a successful mint

The substitution pass fills `{{TOKEN}}`-shaped text. The self-name pass rewrites the
*literal* `rsr-template-repo` and the owner literal. Everything else is left as
written — so free-form self-description prose is in neither net, and a freshly minted
repo keeps asserting that it *is* the template.

== 4. Order of operations that actually works

[source,bash]
----
# 1. Mint (never RSR_NON_INTERACTIVE):
just repo-init < answers.txt        # 14 identity/description + 3 container + confirm
# 2. Repair descriptiles (STATE, ECOSYSTEM), then choose the clade:
#    edit .machine_readable/descriptiles/{STATE,ECOSYSTEM,CLADE}.a2ml
# 3. Initialise git, because the arrival pack wants a repository:
git init -b main && git add -A && git commit -m "chore: mint"
# 4. Regenerate everything derived, in this order:
just claude-md && just coapt && just repo-map
# 5. Gate:
just validate
----

Step 3 before step 4 is not optional: `generate.sh` calls `git rev-parse --show-toplevel`
and dies outside a work tree. Step 4's order matters because `validate-claude-md`,
`validate-coapt` and `validate-repo-map` each fail on a stale artifact — which is the
point of them.

== 5. For the estate

Two things are worth carrying upstream to `rsr-template-repo`:

. `repo-init` should either repair the descriptile self-descriptions or print them as
  required post-mint actions. A mint that is 97% complete as somebody else's template is
  the same *class* of defect as the 211-repo placeholder drift the estate already paid for.
. `CLAUDE.md` should be regenerated as part of the mint. It is the file agents read
  first, and it shipped here with the wrong uuid, the wrong clade and the wrong IS-NOT
  boundary.
